# Shell Debug Controller

Windows用のローカル開発ツールです。ゲーム起動・DLL配置・Git・公開の機能はありません。

## 起動と操作

1. ビルド済みの `app` フォルダ内にある `ShellDebugController.exe` を起動します。同じフォルダのDLLとruntimeconfig.json等も必要です。
2. MODは `ShellDevelopment` ビルドが必要です。公開用 `Release` DLLには接続できません。このツールはゲームDLLを自動配置しません。
3. 同じWindowsユーザー・同じログオンセッションでゲームとアプリを動かします。別の権限レベルで起動した場合、接続できないことがあります。
4. 接続後に最上部の「デバッグモード」をONにし、必要な機能だけONにします。初期値はすべてOFF、設定を次回起動へ保存しません。
5. 親スイッチOFFで子スイッチもOFFになります。アプリ終了・切断・無応答時はMOD側の操作期限が切れ、ZoomとColliderを復元します。部屋変更時も再度ONが必要です。

ゲームが未起動、MODが公開版、ゲームが複数起動している場合は接続・操作しません。アプリ側からゲームを起動・終了することはありません。

スイッチの順序は、デバッグモード、ズーム、壁すり抜け、通信状態、15人用通信状態です。

## ズーム

既存Zoom.csとマウスホイールを使います。ゲーム内の既存「ズームを有効にする」設定もONにしてください。生存中のPC版MOD導入ホスト本人・非公開オンライン試合中だけ使用できます。OFF・会議・試合終了等で、この機能が変更した倍率を元へ戻します。死亡後の既存ズームは公開版でも従来どおり利用できます。

## 壁すり抜け

本人の既存Colliderだけを一時的に無効にします。他プレイヤーのCollider、ゲームのレイヤー設定、役職、RPC番号、保護機能は変更しません。通常の移動同期を利用します。

停止・OFF・会議・試合終了・切断等で衝突を復元します。壁内で停止した場合は、最後に壁と重なっていないことを確認できたTransform位置へ標準の所有者SnapToで戻します。通信失敗時はローカル復元を試み、再試行し続けません。

復帰座標とCollider中心のオフセットを分け、照会結果32個の固定バッファが埋まるなど安全性を確認できない場合はすり抜けを開始しません。ベント・梯子・移動床・操作ロック中も停止します。サーバーの制限を回避する処理はありません。

実ゲームでの壁際、各マップ、役職の強制移動、他端末への同期は実機未確認です。初回は非公開の小規模テスト環境を使ってください。

## 実測の通信状態

- 参加人数：現在のPlayerControl集合から、254以上の描画ダミーと切断済みを除いた数。
- 送信回数・バイト数：`InnerNetClient.Connection_DataSentRaw` コールバックの発生回数とlength引数。受信確認や、実際の回線総量・Reliable再送を独立に測定した値とは扱いません。
- 直近10秒：時刻を保存したローリング集計。16,384件を超える場合は「以上」と表示し、正確な値と偽りません。グラフは1秒バケット。
- 通信エラー：`Hazel.Connection.Send` の非None戻り値と例外。この経路以外の全ネットワーク障害を数えるものではありません。
- Nova：実在するプール数、準備・チャージ・待機・発射状態、非表示/回収待機数。
- Nova固有CNOの送信要求もカテゴリー別に集計し、表示名、Spawn、空名更新のサイズをシミュレーターへ反映できます。

フック登録を確認できない項目は「取得不可」。パケット本文・名前・コード・Tokenは保存しません。OFF中は数値の収集も停止し、集計をクリアします。

## 15人用シミュレーター

15人・1 Novaの表示プールを仮定した、通信を一切送信しない計算です。

- 初期プールは通常10体・Fungle11体・Airship15体、ビーム用3体、最大表示名593Bは対照用の仮定値。実際の幅・フォント・射程のプランを自動測定したものではありません。
- 14宛先を8人単位で割り当て、1秒間隔でプールを生成する現在のCNOモデルに基づきます。
- Spawnと空名更新の基礎フレームは、観測ボタンで取得できるまでは入力欄の仮定値です。初期値256Bは実測値ではありません。
- 割当フレームはpacked intを最大5Bとして計算した保守的な上限。移動要求も既存フレームの上限値25Bを使います。
- 800B表示名、1000B送信要求、時間集中を検知します。大きいデータが自動分割できるとは仮定しません。
- 準備は描画プールの生成を指します。発射、プールの非表示・駐車による回収と比較します。毎回Despawnするモデルではありません。
- チャージ/照準の表示・回転更新、複数Nova、他役職、通常のプレイヤー同期、認証、回線再送、各端末性能を含む完全な15クライアント再現ではありません。

推定値からVanilla PC・スマホ・Switchの切断耐性を保証しません。入力が上限を超えた際も、ゲームやサーバーへ試験送信はしません。

## ローカル通信と制限

名前付きパイプを使い、OSの `PIPE_REJECT_REMOTE_CLIENTS` で別PCからの接続を拒否します。DACLは現在のWindowsユーザーだけ、最初のサーバーだけが所有する設定です。接続相手のPIDをOSから照合し、MODは同じセッションのShellDebugController実行ファイル名を確認、アプリは対象ゲームPIDを確認します。

固定スキーマ、最大要求1024B・応答65536B、単調増加シーケンス、セッション世代、2秒のI/O期限、3秒の操作期限を使います。バックグラウンド通信からUnityへ直接アクセスせず、操作はゲームのメインスレッドに反映します。任意ファイル操作・任意RPC・コマンド実行の入口はありません。

同じWindowsユーザーや管理者権限で動く悪意あるプログラムまで隔離する構成ではありません。異なる実ユーザーや実際の別PCからの攻撃通信は今回試していません。OS設定やファイアウォールは変更しません。

Microsoft仕様: https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-createnamedpipea

## ビルド分離

`Build-Controller.ps1` で公開Release、ShellDevelopment、Windowsアプリを作り、公開用DLLにデバッグ処理が残らないことをCecilで監査します。すべて `CopyToAmongUs=false`。出力は日時付きの `artifacts/debug-controller/` 以下です。以前のNova/CNOのILも比較する場合は `-BaselineDll` に以前の検証済みDLLを指定します。

```powershell
.\Build-Controller.ps1
.\Start-Controller.ps1
```

公開用: `dotnet build TownOfHost.csproj -c Release -p:AllowIsolatedRoleBuild=true -p:CopyToAmongUs=false`

開発用: `dotnet build TownOfHost.csproj -c ShellDevelopment -p:AllowIsolatedRoleBuild=true -p:CopyToAmongUs=false`

Releaseへ開発フラグ・専用シンボルを注入する指定や、ShellDevelopmentの自動ゲームコピーはビルドエラーにします。公開時にデバッグソースを手作業で消す必要はありません。既存Option IDや死亡ズームを削除する処理もありません。

この除外監査は、今回のController連携・通信観測・15人推定・壁すり抜け・生存ズームを対象にします。上流から存在するDebugModeManagerや従来の設定IDを撤去する変更は行っていません。新アプリからそれらの既存デバッグ権限を有効にする処理もありません。

Windowsアプリは.NET 10 Desktop Runtimeを使用します。今回のPCには導入済みです。MODは既存の.NET 6のままです。新しいSDKやランタイムのインストール、公開版の更新、Steam DLLの配置はこの作業では行いません。


### Novaのマップ別描画プール

- 照準の星を含む総数はThe Airshipが15体、The Fungleが11体、それ以外が10体です。
- 「15人用通信状態」のマップ選択で既定数が切り替わります（Airshipは15体）。接続時にマップ情報を取得できれば実際の選択マップへ追従します。取得できない旧開発DLLでは手動選択してください。
- プール数の数値欄は比較用に変更可能です。ゲーム中のダミー数を操作する設定ではありません。
- グラフとフェーズ別通信量は推定です。追加1体は15人モデルで準備送信4回と生成間隔約1秒を追加します。発射時の使用数は幅・TMPフォントの実測形状で決まり、全体数と同じとは限りません。
- 1表示名800B、各名最大12線分、全区間のメッシュ検証、通信分散と失敗時の安全中止は維持します。細いビームは必要な場合に線分の重なりだけを減らし、範囲50と太さを維持します。
- モデル値は再送・通常ゲーム通信・Vanilla端末負荷を含まないため、切断耐性を保証しません。
