# Nova 描画の回帰検証

`dotnet run --project tests/Nova.Runtime.Tests -c Release -p:CopyToAmongUs=false`

製品の `Nova.cs` とプール・命中規則をリンクして実行します。Unity、IL2CPP、
フォント描画、送信先は代替実装です。実際のゲームや外部サービスへ接続しません。

`BuiltinBeamFontMetrics.json` は v19s のローカル `resources.assets` を
読み取り専用で解析した文字の数値です。画像・テクスチャ・フォント本体は含みません。
同名のBlackフォントが複数あり、Resourcesの登録先はObject 304です。
このアセットには `—` がなく、幅34・高さ15の `-` と、幅46・高さ12の `_` があります。
今回、試験的な `_` 優先選択を取り消し、バックアップと同一の `-` 選択・メッシュ位置換算へ戻しました。

描画用代替実装は、文字本体と透明なSDF余白を含むメッシュを別々に生成します。
検証用の文字本体の頂点は製品側の位置逆変換を利用していません。旧描画は透明なSDF余白を含むメッシュで範囲を検査します。メッシュの範囲検証は、実機で不透明な線が50まで連続することの保証ではありません。
文字の種類、回転、独立したX/Y単位、最終メッシュと作業用頂点の違いも扱います。

- `--stretch-repro`: 旧描画のメッシュ範囲を出力する診断。透明余白のあるフォントの可視距離は専用テストで別途記録します。
- `--stretch-bench`: マップ・太さ・角度・横長文字の有無を変えた模擬計測をJSON出力。旧描画では横長文字が存在しても `-` のままです。Airshipは星込み15体です。
- `--map-bench`: 従来のマップ別プール検証。

ベンチマークの割当量にはテスト用レンダラーの処理を含みます。
実際のAmong UsのRAM・VRAM・CPUやVanilla端末の表示・切断耐性は計測していません。
GPUのアルファ表示、端末ごとのフォント・クリッピングなどは実機検証が必要です。
