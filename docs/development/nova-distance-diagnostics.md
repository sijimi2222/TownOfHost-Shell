# Novaの表示距離を調べる開発版ログ

`ShellDevelopment`だけに含まれる観測機能です。公開用`Release`には入りません。
描画・ダミー数・射程・命中判定・カメラ・通信・設定は変更しません。
`ForceMeshUpdate`、文字や材質の書き換え、追加RPC、画像キャプチャは行いません。

## 確認済みの事実と未確定事項

2026-11-08 23:16:50 / 23:17:26の実機`BepInEx/LogOutput.log`では、
プール15体、`reach=50`、`glyphs=20`、`chunks=2`、`bar=3.589`でした。
発射計画がビームへ割り当てたのは2体、ビーム用の予備が12体、星が1体です。
発射中の星は非表示なので、発射中に表示していない数は計13体です。
既存ログは各Rendererの表示完了やVanillaへの到達を記録していないため、
実際に描画・送達された数は今回追加したrender診断で確認します。

`GlyphCount`は射程と文字の実測幅から必要数を求め、1体12文字以下で分割します。
容量はAirshipで14×12=168文字、全体上限192文字ですが、この発射は20文字です。
総数を増やしても必要数と終点50は変化しません。800B上限にも達していません。
全ダミーを射手の座標に置き、文字の`pos`/`voffset`で遠方へ配置する方式です。

これは「総数を増やしても長さが変わらない」理由です。実画面で50より短く見える
直接原因はまだ確定していません。TMPメッシュ、SDFの透明余白、材質のクリップや
ステンシル、名前UIの状態、カメラ範囲、端末ごとの描画を分けて観測します。
ローカルPrefabの折り返し・自動縮小はOFF、オーバーフローはOverflowですが、
実行時に同じ値であることや、Vanilla端末の表示までは証明していません。

## 出力場所・識別

通常の`BepInEx/LogOutput.log`に、`[NovaDistance]`タグの1行JSONを出力します。
Steam標準配置なら次のファイルです。

`C:\Program Files (x86)\Steam\steamapps\common\Among Us\BepInEx\LogOutput.log`

ログ保存操作で作成するShellのログにも、同じタグが含まれます。
専用ファイルや毎フレームのファイル書き込みは追加していません。
Controller接続は不要です。既存Loggerが有効な開発版ホストで観測します。

- `revision=nova-distance-diag-v1`：今回の診断機能。
- `stage=identity`：プロセス内で1回。ロード済みモジュールの`mvid`と、
  その配置ファイルの`onDiskSha256`、製品バージョン、開発用マーカー。
- `stage=plan`：発射直後。マップ、所有者ID、プール、使用数、予備数、上限、
  発射位置・方向・描画計画の始点/終点・命中判定の始点/終点、各ダミーの位置。
- `stage=render`：可視状態の確定から約0.12秒後に1回。現在の文字が計画と
  一致するか、最終メッシュの範囲と欠落、文字数、TMPの設定、材質・ステンシル・
  クリップ設定、子MeshRenderer、カメラ座標・画角・端点のviewport座標。
- `stage=cleanup`：終了/会議/破棄時に1回。表示と回収状態。描画前の安全中断は
  `plan`のキャンセル理由と合わせて確認します。

1試合の先頭64発まで、1発につき最大3行、1行32,768文字までです。
通常更新では同じメッシュを繰り返し読まず、診断中の例外はゲームへ伝播させません。
投稿者名、プレイヤー名、部屋コード、外見データ、表示名の全文は出力しません。
`owner`はゲーム内の一時PlayerIdであり、Discord ID等ではありません。

`observedMeshComplete`はホストのメッシュ範囲の判定です。
`estimatedInkMin/Max`は文字メトリクスに基づく推定で、GPUで見える不透明ピクセルの
実測ではありません。Vanilla参加者の表示や切断耐性の保証にもなりません。
読めない値は`unknown`/`unavailable`として、50へ到達したと仮定しません。

## 最小限の実機確認

今回の作業ではDLLを配置していません。配置が別途許可された後に行います。

1. 新しいShellDevelopment DLLのSHA-256とMVIDを確認して配置する。
2. 非公開のAirshipテスト部屋でNovaを1人配役し、準備完了を待つ。
3. 壁越しに水平1回・垂直1回発射する。開始位置と方向が分かる録画を残す。現在はAirshipのreachが70、その他が50。描画計画の終点とhitEnd、observedMeshMaxを同じ射程で確認する。
4. 既存ズームを使い、ビーム終点がカメラ内に入る倍率でも確認する。射程70を全方向で見る試験では75程度まで広げ、カメラ端による見切れと描画不足を区別する。
5. `[NovaDistance]`のidentity、plan、render、cleanupと、同時刻の
   `[NovaTraffic]NOVA_DRAW_PLAN`を保存する。
6. `matchesPlannedText`、実メッシュの終点、文字数上限、マスク/クリップ設定、
   両カメラのviewportとcullingMaskを確認する。
7. ホストで原因を絞った後、Vanillaを1人だけ追加して同じ方向を比較する。
   ホストの診断だけではSwitch・スマホ側のメッシュや画面を観測できません。

### 判断例

- メッシュ自体が50へ届かない/欠ける：実行時のTMP設定、文字置換・位置換算を調査。
- メッシュ50、`matchesPlannedText=false`：名前更新・表示上書きを調査。
- メッシュ50、終点viewportが画面外：その画角では50まで見えない。
- メッシュ50、画面内、見た目が短い：材質・ステンシル・シェーダー・GPU描画を調査。
- ホストだけ正常：Vanilla側の名前描画・フォント・外見更新を追加検証。

いずれもログ1項目だけで原因と断定せず、同時刻の録画・カメラ条件と照合します。
調査終了後は`NovaDistanceDiagnostics.Enabled=false`で停止でき、2つのDiagnostics
ファイルを開発ビルドの対象外にすれば整理できます。公開ビルドは常に対象外です。
